# 中岛美雪歌曲解读页 · 制作工作流

本仓库是一个纯静态网站：每首歌一个页面 `songs/<slug>/index.html`，首页卡片由 `songs.js` 生成。
这个技能把“拿到歌词 → 做出一页和现有六首风格完全一致的解读 → 加进网站”的全过程固定下来。

同目录文件：

| 文件 | 用途 |
|---|---|
| `template.html` | 新页面模板。**必须从它复制开始**，CSS 与渲染脚本一个字都不要改动（专属装饰除外）。 |
| `已讲语法索引.md` | 前几首讲过的全部语法点。新歌再次出现时要标“回顾”。 |
| `scripts/check_song.py` | 校验页面：数据格式、引用、ruby、页脚编号、songs.js 是否已登记。 |
| `scripts/grammar_index.py` | 新歌完成后重新生成 `已讲语法索引.md`。 |

现有页面就是最好的范例，写之前至少通读一页（推荐 `songs/headlight-taillight/index.html`，最短；`songs/utahime/index.html` 有副歌重复的典型处理）。

## 0. 读者与目标

- 读者是 **Nick**：中岛美雪的听众，**日语初学者**，母语中文。
- 页面要同时做到三件事：讲清楚这首歌（背景与含义）、给出好读的中文译文、让初学者能借这首歌学日语。
- 全部用**简体中文**写，语气平实、有温度，不堆砌形容词，不写空话。

## 1. 输入：歌词

- Nick 持有正版专辑，会给出完整歌词，常见形式是 `.lrc` 文件。
- `.lrc` 多为 **UTF-16** 编码，先转码：`iconv -f UTF-16 -t UTF-8 歌名.lrc > /tmp/歌名.txt`。
- 去掉时间戳 `[mm:ss.xx]` 和元数据行（`[ti:]`、`[ar:]` 等）。
- **.lrc 里自带的中文翻译一律忽略**，译文全部自己重新翻。
- 按原曲演唱顺序保留**全部**歌词，包括重复的副歌。
- 歌词不全或有疑问的字，先问 Nick，不要自己补。

## 2. 制作步骤

1. **确认基本信息**：歌名（日文原题＋汉字读音）、中文译名、年份、编曲、收录专辑、用途（电视剧/电影/夜会等）。查资料（日文/英文维基百科、官方资料、可靠媒体报道），记下来源 URL，页脚要列出。查不到的不写，不编造。
2. **定 slug 与编号**：slug 用罗马字小写＋连字符（如 `nisekino-fune`、`headlight-taillight`）；编号 = `songs.js` 里最大的 `no` + 1。
3. **复制模板**：`cp .claude/skills/miyuki-song/template.html songs/<slug>/index.html`。
4. **分段**：把歌词分成若干 stanza（第一段 / 副歌 / 第二段 / 间段 / 尾声……），每段起一个中文小标题，格式 `第一段 · 被遗忘的星名`。
5. **写 D 数组**（见第 4 节）：先全部写好日文＋注音＋意译＋直译，再逐行补单词表和语法点。
6. **写主页面正文**：创作背景、标题释义、全曲解读、译法小记（见第 5 节）。
7. **写学习页的语法速查卡**：把本曲讲过的语法浓缩成 12～16 张小卡。
8. **hero 区**：填年份、标题、中文名、制作信息；按需要加一个呼应歌曲意象的小 SVG（见第 6 节）。
9. **加入网站**：在 `songs.js` 末尾加一项（见第 7 节），页脚写对“第 N 首”。
10. **校验**：`python3 .claude/skills/miyuki-song/scripts/check_song.py songs/<slug>/index.html`，必须“✓ 通过”。再用浏览器打开页面，点几句歌词确认能跳到学习页对应位置，手机宽度下没有横向滚动。
11. **更新语法索引**：`python3 .claude/skills/miyuki-song/scripts/grammar_index.py`。
12. **提交推送**：`git add -A && git commit -m "新增：《歌名》解读" && git push`。Cloudflare Pages 会自动部署。

整体意象是**夜海与月亮**：深海蓝的夜空 hero、米色纸张感的正文、赭红作强调色。

| `--paper` | `#f7f1e6` | 页面底色（米色纸） |
| `--paper-2` | `#efe6d5` | 次级底色（note、语法框） |
| `--card` | `#fffaf1` | 卡片底色 |
| `--ink` / `--ink-soft` | `#2b2622` / `#5d544c` | 正文 / 次要文字 |
| `--sea` / `--sea-2` | `#1f3a4d` / `#2f5670` | 深海蓝：标题、日文、表头 |
| `--ember` | `#a4472d` | 赭红：h3、假名注音、主按钮、译文 |
| `--gold` | `#b48a4a` | 金：章节号、段落标签、引用线 |
| `--line` | `#dccfb8` | 分隔线、边框 |

- 字体：中文 `Noto Serif SC`，日文 `Shippori Mincho`（Google Fonts）；罗马音用 Georgia 斜体。
- 版心 860px；正文 17px，行高 1.9。
- hero：`#0f2130 → #1f3a4d → #2f5670` 的竖向渐变，星点＋闪烁的星＋月亮＋底部两层波浪。

## 4. 数据格式：D 数组

歌词与学习页内容全部写在页面底部 `<script>` 的 `var D=[...];` 里，由前端渲染成两处：主页面的对照歌词、学习页的逐句讲解。这样页面体积小，也保证每首歌排版一致。

**必须是合法 JSON**：只用双引号、不要尾逗号、HTML 里的双引号写成 `\"`。`var D=` 要单独一行开始，以 `];` 结尾并换行（校验脚本靠这个找它）。

```js
var D=[
  ["段落标题", [ 行, 行, ... ]],          // 普通段落
  ["副歌 · 再一次", [ 行, ... ], true],   // 第三项 true：整段不进学习页（每行都必须带引用 id）
];
```

**每一行正好 8 项：**

| # | 字段 | 说明 | 例 |
|---|---|---|---|
| 0 | id | 本页唯一。主歌 `l1 l2…`，副歌 `c1a c1b…`，也可按段用字母前缀（`v1`、`p1`、`a1`）。 | `"l3"` |
| 1 | 日文 | 原文。汉字注音写 `{漢字|かな}`，一组汉字一组读音；两行合成一句时用 `<br>`；歌词里的全角空格照原样保留。 | `"{紛|まぎ}れ{散|ち}らばる{星|ほし}の{名|な}は"` |
| 2 | 罗马音 | 小写赫本式，按**实际发音**：は→wa，へ→e，を→o，长音用 ā ī ū ē ō。 | `"magire chirabaru hoshi no na wa"` |
| 3 | 意译 | 信达雅的中文译文，显示在对照区和学习页。 | `"那些飘散、隐没其中的星辰之名"` |
| 4 | 直译 | 贴着日文语序的字面意思，帮助初学者对照结构。 | `"混杂而散落的星星的名字"` |
| 5 | 单词表 | `[[词, 读音, 词性, 释义], …]`，按句中出现顺序。 | 见下 |
| 6 | 语法点 | `[[标题, 说明HTML], …]`，一般 2～3 个。 | 见下 |
| 7 | 引用 id | 与前面某句相同（或几乎相同）时填那句的 id，此时 2、4、5、6 留空（`""`、`[]`）。否则填 `""`。 | `"c1a"` |

**单词表**

- 读音：假名词写假名；助词等写罗马字（`"wa"`、`"e"`、`"no"`）以提示发音；外来语写罗马字（`"heddoraito"`）。
- 动词先列辞书形，必要时再列变形本身：`["忘れる","わすれる","动","忘记"], ["忘れられる","わすれられる","动","忘れる 的被动形：被忘记"]`。
- 复合词先拆再合：`語る` / `継ぐ` / `語り継ぐ`。
- 词性用这些标签（`动` 显示蓝色、`助`/`终助` 显示红色）：
  `名 动 形 な形 副 助 终助 助动 补助动 代 连体 接续 疑 叹 数量 后缀 接尾 句型 句`

**语法点**

- 标题写“形式＋一句话含义”：`"〜ても：即使……也"`、`"动词ない形：う段→あ段＋ない"`。
- 已在前几首讲过的，标题加 `（回顾）`，说明里点明出处：“《二隻の舟》里讲过”。查 `已讲语法索引.md`。
- 说明里的日文例子包在 `<span class=\"ex\">…</span>` 里；可以用 `<b>`、`→`、`＝`、`｜`（标出修饰语与被修饰语的分界）。
- 易错点用 `⚠` 开头，例如 `"⚠ あどけない 不是否定！"`。
- 除了语法，也可以讲修辞、意象、用词选择（“诗的修辞：时光‘落下’”、“称える ／ 誉める”）。

**完整一行示例**（出自《ヘッドライト・テールライト》）：

```js
["l4", "{忘|わす}れられても", "wasurerarete mo", "纵然早已被人遗忘", "即使被忘记",
 [["忘れる", "わすれる", "动", "忘记"],
  ["忘れられる", "わすれられる", "动", "忘れる 的被动形：被忘记"],
  ["ても", "te mo", "助", "即使……也"]],
 [["被动 〜られる（回顾）", "一段动词去掉 る 加 <span class=\"ex\">られる</span>：<span class=\"ex\">忘れる→忘れられる</span>。在《二隻の舟》里讲过。注意：<span class=\"ex\">忘れられる</span> 也可以是“能忘记”（可能形），要靠上下文判断，这里显然是“被忘记”。"],
  ["〜ても（回顾）", "<span class=\"ex\">忘れられて＋も</span>＝即使被忘记。句子在这里停住，答案留给副歌：“旅途还没有结束。”"],
  ["省略的主语", "被<b>谁</b>忘记？歌词没说，也不需要说：是整个世界。日语常把不重要或不言自明的主语省掉。"]],
 ""]
```

**重复的副歌**（引用行）：

```js
["c1b", "ヘッドライト・テールライト<br>{旅|たび}はまだ{終|お}わらない", "", "前灯，尾灯，这一程，还远远没有完", "", [], [], "c1a"]
```

- 主页面对照区**按原曲顺序全部列出**；学习页只完整讲第一次，其余显示为一张小卡“↺ 与前面的「…」相同，讲解见那里”。
- 同一句副歌反复多次时，意译可以在两三种说法之间轮换，免得读起来单调（headlight 就是这样）。
- 一整段都是重复（例如第二遍完整副歌）时，可以给该段加第三项 `true`，学习页直接跳过整段（见 `songs/sejou/`）。

## 5. 写作与翻译原则

### 翻译：信、达、雅

- **信**：不违原意，不添原文没有的情绪和信息。
- **达**：读起来是自然的中文，不留日语语序的痕迹（字面结构交给“直译”栏）。
- **雅**：保留诗意、节奏和意象；不逐字硬译，必要处可略作演绎，但演绎了就要在“译法小记”里说明。
- 一个日文词身上叠着两层意思时，尽量让中文也带上两层（例：`過ぎても` → “只献给英雄，从我们身旁掠过”）。
- 原文刻意重复或对仗的，译文也保持重复或对仗。

### 第壹部分：创作背景与歌曲含义

- `.facts` 信息卡 3～4 张：发行时间、收录专辑、用途、其他亮点。
- 2～3 个 `h3` 背景小节：时代背景 / 影视或舞台背景 / 版本说明。
- 一节“标题：……”解释歌名（字面义、引申义、为什么这么起）。
- 一节“全曲解读 · N 个层次 / 镜头 / 幕”：`<p><b>一、小标题。</b>正文</p>`，按歌词推进的顺序，4～6 层；可引用日文原句（`.jq`）。
- 至少一个 `<blockquote>` 点题。
- 带个人色彩的读法要注明“（这是一种读法，并非作者说明。）”。
- 可以联系前几首（“那是《瞬きもせず》的做法”），让系列互相呼应。
- 事实要有来源；不确定的说法用“据说”，查不到就不写。

### 第贰部分末尾：译法小记

挑 4～6 处最值得说明的翻译取舍，格式：

```html
<p><b>“原文” → “译文”</b>：为什么这么译、放弃了什么、和别的译法比好在哪里。</p>
```

### 第叁部分：学习页

- 读者是**初学者**：先讲最基本的（语序、助词、动词变形），一句里挑最有学习价值的 2～3 个点，不要堆满。
- 用中文类比解释，多举一个日常例句。
- 跨行的长定语要提醒“拼起来、从后往前翻”。
- 文语、歌词特有的读法（`行く` 读 `ゆく`、`〜ぬ` = `〜ない`）要专门指出。
- 速查卡 `.cheat`：每张 `<div><b>形式</b>一句话说明＋本曲例词</div>`，标出“（回顾）”。

## 7. 加入网站

1. 页面放在 `songs/<slug>/index.html`。模板里已有两处 `<a href="../../">⌂ 首页</a>` 和页脚的 `· 第 N 首`，填对编号即可。
2. 在 `songs.js` 数组末尾加一项：

```js
  {
    no: 7, slug: "<slug>",
    title: "{漢字|かな}の…",          // 日文歌名，ruby 写法与 D 相同；纯片假名/英文直接写
    zh: "中文译名", year: 1985,
    source: "专辑《…》· 电视剧《…》主题曲",   // 一行出处，用 · 分隔
    blurb: "一两句话的导读，40～50 字，说出这首歌最打动人的地方。",
    tags: ["关键词", "关键词", "关键词"]     // 3 个
  }
```

3. 跑校验脚本和语法索引脚本，提交并推送。
